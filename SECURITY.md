# Security and data handling

Direct mode sends Claude Code's system instructions, tool definitions, conversation, and returned tool output to Microsoft 365 Copilot through its logged-in chat UI. This can include source code, file paths, command output, secrets and image contents read by the client. Base64 images are uploaded through the Copilot UI as real file attachments; the request text uses stable image-hash references instead of pasted base64. Choose workspaces and tools accordingly. The bridge does not automatically redact native request contents: redaction would change the model's context.

The gateway binds to `127.0.0.1`, authenticates client requests, and pairs one Chrome extension using a one-time local code. Keep it on loopback; do not expose it through a reverse proxy, LAN listener or public tunnel. Browser responses are untrusted and validated against the supplied tool schemas. Claude Code executes tools locally using its own permissions.

The extension requests `activeTab`, `scripting`, `storage`, `alarms` and loopback access. Its optional Office permission upper bound is `https://*.officeapps.live.com/*`; pairing requests the two exact frame origins `https://fa000000124.officeapps.live.com/*` and `https://excel.officeapps.live.com/*`. The default `npm run build` text extension does not request cookies, history, debugger, native messaging or filesystem access. The optional **image build** (`npm run build:images`) instead adds the required Chrome `debugger` permission. [Chrome does not allow that permission in `optional_permissions`](https://developer.chrome.com/docs/extensions/reference/api/permissions), so it cannot be granted/revoked as an optional runtime permission. Installing/reloading the image build expands the extension's privileges and needs explicit user approval. This is a powerful browser-wide permission: Chrome does not restrict its potential API scope to our paired tabs. The image build requires Chrome 125+. The input driver temporarily emulates active page focus only for a verified image job's tab and its related exact-origin Excel/Copilot iframe targets. It recursively attaches flattened child sessions only under that tab and rejects unrelated frames, then checks nonce/page/draft/model and the identities of both the editor and native Send button, focuses that exact button, sends one Enter and verifies a trusted Enter reached it. During this input operation, bounded diagnostics record only Enter and its Send-button activation-click metadata (such as trusted status, composition and selection/focus flags), never text or other keys. Their listeners are removed as soon as the input operation finishes. Failed state proofs report only boolean comparisons and counts, never the compared prompt/draft strings. Loaded image previews and the complete unique inline File references are checked inside the current composer before the exact draft is frozen; historical thumbnails do not qualify. Visible upload indicators also block input, including decorative presentation-role or aria-hidden spinners. After dispatch, acknowledgement is read-only: transient editor changes and new human drafts are neither overwritten nor treated as delivery proof. Enter is released immediately after dispatch. Target-page focus emulation and the debugger attachment remain scoped to that job until its exact user message is acknowledged, cancellation occurs, or the acknowledgement deadline expires (15 seconds in the page, with a 20-second worker channel limit). A click alone is not delivery proof. It restores focus emulation, releases Enter and detaches even on failure; it does not bring the browser window forward. It exposes no general CDP command interface and does not use network, cookie, storage, or other-tab inspection commands. Chrome can show a debugging banner. A debugger already attached by another tool is never disconnected by the bridge; attachment failure is reported without retrying input. Image input also has a default-off runtime switch. Disabling it or disconnecting stops its use but does not remove the required permission; rebuild/reload the default text extension or uninstall to remove that privilege. It reads the logged-in Copilot chat DOM rather than exporting Microsoft passwords or login tokens.

Bridge state is in `~/.m365-claude-bridge` (or `M365_BRIDGE_STATE_DIR`). It includes local authentication credentials and context metadata. POSIX files use private permissions; Windows relies on the user profile's access controls. Gateway metadata does not persist source conversation bodies or image bytes. Image pixels are held only for the active/queued transport; the content script clears completed pixel payloads and journals only attachment IDs with the reply. Copilot may retain the uploaded attachment with its chat; manage Microsoft-side data in that service. The extension journals pending replies until acknowledged; interrupted replies may remain until disconnected. Claude Code itself maintains its normal local transcripts, which can contain the complete request and tool output. Killing a launcher can leave a private temporary session settings file; remove it after that client has exited.

The extension remembers local gateway URLs, worker IDs and pairing tokens for Windows/WSL switching in Chrome local extension storage. This does not include Microsoft credentials. Only one gateway is connected at a time; finish pending requests before switching. Browser profile access can reveal these local tokens, so protect that profile as well as the gateway state directory.

Disconnect in the extension to remove all saved gateway pairings, pending replies and optional host grants. Stop the gateway with `node dist/packages/cli/index.js stop`. These actions do not delete native Claude Code transcripts or Microsoft chat history. Manage those separately in their respective applications.

## Reporting vulnerabilities

Do not post credentials, exploit payloads containing private data, or a working account/session in a public issue. After this project is published, use its GitHub **Security → Report a vulnerability** feature when private reporting is enabled. If it is unavailable, open a minimal issue asking for a private reporting channel, without exploit details. The initial release checklist requires enabling private reporting.

There is no guaranteed response time for this experimental project. For ordinary installation and UI issues, use a redacted bug report.
