# Supported scope and limitations

This experimental integration drives an authenticated web chat, rather than a supported Microsoft Anthropic-compatible API. The visible UI, localization, account access and model labels can change. Copilot's own instructions and service policies remain in effect. The bridge does not bypass a refusal or request access to models absent from the account.

- **Tools:** Claude Code executes local tools with its native permissions. Tool names/arguments are validated against the request's schema. Successful Read/Write/Edit/Bash checks do not establish compatibility with every plugin, MCP server, subagent or permission mode.
- **Image permission:** Image input is opt-in and requires an explicit image build with the powerful required Chrome `debugger` permission for a single Enter activation of the verified native Send button. The default text build does not require it; a runtime switch stops use without revoking the image build permission. Another active debugger, permission revocation, changed draft/page or unconfirmed delivery stops the image request; it is never automatically sent twice.
- **Content:** Text and base64 PNG/JPEG/GIF/WebP images from native Read/user messages are supported. Pixels are real Copilot attachments; text history uses stable hash references. The bridge limits each image to 5 MB, unique image data in a request to 10 MB, and a browser turn to five attachments. Missing attachment verification fails explicitly. Remote image URLs, audio/video/document blocks, signed thinking and full reasoning-block compatibility remain unsupported.
- **Reply format:** A completed native reply that starts with the JSON envelope/code fence but has invalid JSON syntax gets at most one formatting follow-up in the verified same chat and model. The original reply's tools are never executed; corrected output must still pass every envelope, tool-schema and tool-choice check. Unverified delivery, invalid tool arguments, arbitrary prose, explicit refusals or a second malformed reply stop explicitly. This reduces format interruptions; it cannot guarantee every upstream response is valid.
- **Streaming:** SSE heartbeats keep the client informed while Copilot generates; answer events are buffered until the UI response completes. This is not upstream token streaming.
- **API controls:** Requested effort, output size, beta flags and cache metadata can be serialized as instructions, but cannot be enforced as real API controls. Prompt caching and measured provider billing are unavailable.
- **Usage:** Context/token meters and costs calculated by the client do not measure actual Copilot service usage. Counts are local estimates, exposed as such by the launcher, doctor and response headers.
- **Concurrency:** One paired gateway and one lead native session per workbook, with isolated subagent/in-process teammate tabs and serialized browser inference. Up to 16 agent tabs are retained. Do not change their active chats mid-request. Title/summary tabs remain separate. Split-pane team processes were tested and failed: separate native children omitted agent identity, causing lead-context 409 errors after browser chat changes. Use in-process teammates. Native panel stop may leave an already pending HTTP request running; the gateway can cancel only when the client disconnects. Native Auto mode passed the limited three-teammate Write/Read/Bash continuation check described in [validation.md](validation.md); its classifiers add browser requests and latency, and arbitrary tasks remain unverified.
- **Recovery:** Chrome must stay running, logged in, with the workbook and Copilot available. Sleep, discarded tabs, expired login or gateway restarts can interrupt a request. Ambiguous delivery fails explicitly rather than replaying.
- **Lifetime records:** There is no fixed cumulative count limit for conversation, native-context or compaction registrations. Valid records survive restart; they are not automatically evicted to make room. This does not change the separate active-tab, queue, request-size or provider context limits.
- **Capacity:** Approximately 500k local estimated input and compaction were tested on selected sessions. Neither a 1m upstream window nor reliable arbitrary unattended long histories is certified.
- **Platforms:** Windows Claude Code and Ubuntu WSL with Windows Chrome were exercised locally. Automated Linux fixtures do not establish live macOS/browser/account compatibility.
- **Desktop Excel:** The separate Windows accessibility transport supports advisor mode only. It may briefly focus Excel and cannot replace native Claude Code inference.

Direct mode transmits the native client's context to Copilot, including any code and tool output it contains. Review [SECURITY.md](../../SECURITY.md) before choosing a workspace.
