# Native context, browser chats and compaction

Claude Code remains the source of the conversation. Its request contains the system instructions, available tool schemas, messages and tool results. The bridge serializes text and stable image references into Copilot chat prompts, sends base64 image pixels separately through real browser attachments, and validates the structured response before returning native text/tool events.

The main lane bootstraps full context once, then sends appended messages and changed request fields to the verified active Copilot chat. A changed tool list can still produce a large update. The bridge compares the current browser conversation fingerprint before continuing. It does not restore arbitrary old Office chats from the history sidebar. Keep one active main client session per paired workbook.

Subagents and in-process teammates use native `x-claude-code-agent-id` together with session ID and model. Their independent leases, snapshots, browser lanes and owned tabs preserve continuation when another agent takes its turn. Agent compaction hints and hook events are scoped to the requesting agent. Model requests queue globally; queued requests have a bounded wait budget separate from their generation timeout. A canceled queued request is never sent to the browser. Overlapping main requests for the same session/agent/model still fail rather than mixing histories.

Title requests and native compaction run in bridge-owned auxiliary browser tabs/chats. They do not append to the main conversation. Seeing these additional sessions in Copilot is expected. A long source is transmitted in ordered packets, each acknowledged before the next is sent. The final packet asks for the actual response; intermediate acknowledgments are not native model answers. The UI packet cap is 350,000 characters; serialized escaping reduces each packet's available source capacity. Source text is not silently truncated.

## Image inputs

Image input requires the explicit `npm run build:images` extension build and a separate default-off **Enable image input** switch in the popup. The image build adds Chrome's required `debugger` permission; the default text build does not. Chrome does not permit `debugger` as an optional runtime grant. The extension verifies job/lane/tab/frame, originating document, a nonce, allowed model attempt, unchanged prompt/images and the same observed editor and native Send button before and after attaching. It temporarily emulates focused-page state in that target tab, requires both native Send-button focus and document focus, sends one Enter, verifies trusted delivery to that button, releases Enter immediately, then waits read-only for the exact owned user message before restoring page-focus emulation and detaching. Every current inline File reference must be present with its exact attachment filename before the unchanged draft is frozen. The current draft thumbnail must be fully loaded, and actual attachment-upload indicators block input even if the preview and Send button are already visible. The decorative upload spinner need not expose a progressbar role. After input, draft mutations are preserved while the bridge waits read-only for the owned message. Cancellation or bounded acknowledgement failure releases the connection without another submit. This permission is inherently broader than this build's narrow commands; see [SECURITY.md](../../SECURITY.md). It never detaches another debugger. Unknown delivery is not retried. A permitted summary-model fallback has its own ordered submission identity, rather than resending a prior attempt. Switching the feature off or disconnecting stops its use; removing the required permission needs a default text rebuild/reload or uninstall. Matching content capability, image build permission and enabled switch are required before the gateway leases an image request.

Native Read results may contain image blocks nested inside `tool_result`. These are validated as base64 PNG/JPEG/GIF/WebP, fingerprinted, and replaced in the textual request by a deterministic attachment filename. Only images required by the current bootstrap/delta/replacement tail are uploaded; unchanged old images are not resent during ordinary feedback. The sent browser message must contain independently verified loaded attachment thumbnails for every expected filename (plain prompt text is not accepted as evidence), and its authenticated result must return matching image IDs before a native answer is delivered.

This prevents a valid image in native history from permanently blocking every following request with an unsupported-content 400. Existing sessions that failed only during image validation can continue after updating matching gateway and extension builds; they retain their image source and native tool history. Unknown delivery and genuine upstream refusals retain their separate recovery rules below.

The transport limits are 5 MB per image, 10 MB of unique image data in one native request and five attachments in a browser turn. It never silently truncates or substitutes a textual visual guess. Remote image URLs are not fetched. Image-related token estimates use a fixed local allowance rather than counting base64 as text; they are not measured visual token usage.

Image interpretation uses Copilot's built-in attachment/vision capability. The reference is not a text-only native Read result. Restricting all visual analysis can also prevent that built-in viewing; no local OCR or external vision tool is automatically invoked. A verified thumbnail proves the attachment was delivered, not that a model interpreted it correctly or that a particular internal vision model processed it. Check the actual answer against a known image.

## Thresholds

The launcher applies native model overrides and `CLAUDE_CODE_AUTO_COMPACT_WINDOW` in a temporary session settings file. Its default is `533000`, with the older percentage override cleared. The tested Claude Code build reserves enough room that this targets roughly 500k input tokens. Change the native threshold with `--compact-window 200k` or another supported integer from 100k to 1m. Reserves and recognition behavior can change with client versions.

The gateway's independent prompt cap is measured in **characters**, not tokens. The default is 180,000 characters. Long-context operation requires starting it with `--max-prompt-chars 2000000` (the maximum). A larger client window alone does not increase this transport cap. Token counters are local heuristics, especially approximate for mixed-language text and tool schemas.

## Compaction

1. Native Claude Code requests manual `/compact` or automatic compaction.
2. The bridge sends the complete summary request to a fresh auxiliary chat, using GPT-6.1 Sol.
3. Recoverable UI/JSON-format errors can start a fresh GPT-6 Sol attempt. Cancellation, policy refusals, unsent drafts and unexpected chat changes stop the chain.
4. Only a text response containing a nonempty task-summary section is accepted; a historical answer or tool request is rejected. This structural check cannot guarantee perfect factual fidelity.
5. Native PreCompact/PostCompact hooks reset tracking for the main context, so the next main turn bootstraps the authoritative compacted native conversation.

Sending the full pre-compaction source can take several UI messages and minutes. Summaries are lossy; continue using fresh file reads to verify current state. A client-configured 500k threshold and selected-account acceptance do not prove a provider-wide 1m deployment limit.

## Cancellation and recovery

The bridge separately tracks browser-delivered input and native-committed history. Cancellation enters a confirmation phase for up to 15 seconds. The authenticated receipt binds job ID, nonce, conversation, lane, page instance and message fingerprints; it is stored before acknowledgement. The page must have no Stop button, an available input and stable evidence across observations. No reply, partial JSON and a just-completed reply are all valid cancellation states. None of their proposed tools is returned for execution.

Explicit new feedback waits for this phase. Verified cancellation continues the original chat and epoch with a tail replacement containing new feedback and actual tool results. Unchanged instructions and tool definitions are omitted. Merged tool-result feedback and trailing system environment messages are supported. An incomplete first/bootstrap transfer cannot borrow context from a different chat.

If the original chat is unavailable or unverified, each feedback identity gets at most one isolated full rebuild, including across retries that change only `max_tokens`. The old workbook page and drafts remain intact. A successful rebuild adds a visible synchronization notice to the native response. Oversized full recovery fails explicitly without hanging the native request. Ordinary post-completion feedback uses normal deltas; compaction and substantive history rewrites remain full sync boundaries.

If the paired main tab disappears after the native client has started but before its first main request, a completed auxiliary title must not strand that request in the queue. A cancellation-capable worker verifies the original binding even when its last readiness flag is false. Only an explicit conversation-unavailable failure with submitted=false permits one isolated bootstrap recovery. The first committed context keeps epoch 1 consistently in the prompt, response and registry. Transiently hidden panes can recover in place; unknown delivery and provider refusals do not trigger this fallback. Startup before any ready pairing still requires the normal workbook/pairing checks.

Provider refusals are terminal and preserve their original error across retries/restarts; no chat/model fallback is attempted. Late refusals tied to the same page and user-input fingerprint are also terminal. Old uncertain records without trustworthy checkpoints cannot invent evidence: use explicit `context-reset --session <native-session-id>` only after checking actual tool effects. Reset does not undo files or commands and does not resolve a provider refusal.

Install matching gateway/extension builds, reload the extension and refresh the workbook; `capabilities.cancelContinuation` must be `1`. Same chat identity, unchanged epoch and smaller transmitted deltas are observable continuity evidence, not proof of provider-side cache hits.

The launcher lists only the supported Opus/Sonnet 5.5 native IDs and their Copilot deployment IDs in session-only `availableModels`. This keeps native model selection and Auto-mode classifier routing within the gateway model set. The native classifier remains responsible for each permission decision. Saved global provider/permission settings are not edited.
